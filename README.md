# Экспорт ФГИС ЛК: выделы и защитность

## Назначение

`fgislk_export.py` позволяет выбрать регион и одно, несколько либо все центральные лесничества. Скрипт выгружает:

- центральные лесничества;
- участковые лесничества;
- кварталы;
- лесотаксационные выделы и их подробные атрибуты;
- категории защитных лесов и особо защитные участки из шести слоёв ФГИС ЛК;
- пространственную таблицу связей между выделами и защитными объектами.

## Установка

```bash
python -m pip install -r requirements.txt
```

## Запуск

Интерактивный режим:

```bash
python fgislk_export.py
```

В Jupyter:

```python
%run fgislk_export.py
```

Скрипт открывает окно выбора папки загрузки (последняя выбранная папка запоминается в `~/.fgislk_export.json`), затем спрашивает регион и лесничества. Если в папке есть незавершённая загрузка, скрипт предлагает её продолжить. В Jupyter прерывание ядра (кнопка «Стоп») останавливает загрузку без перезапуска ядра; повторный `%run` с той же папкой продолжает её.

Командная строка (папка задаётся параметром `--out`):

```bash
python fgislk_export.py --list-regions
python fgislk_export.py --list-forestries 26
python fgislk_export.py --region 26 --forestry 26:4 --out D:\FGISLK\essentuki
python fgislk_export.py --region 26 --forestry 26:4,26:7 --out D:\FGISLK\kmv
python fgislk_export.py --region 26 --all-forestries --out D:\FGISLK\stavropol
```

Короткий тест:

```bash
python fgislk_export.py --region 21 --forestry 21:1 --max-quarters 1 --max-pieces 30 --out test --no-pause
```

Параметры:

| Параметр | Назначение |
|---|---|
| `--out` | папка загрузки; без него в интерактивном режиме открывается окно выбора |
| `--geojson`, `--csv` | дополнительно записать каждый слой в GeoJSON или CSV (по умолчанию создаётся только GPKG) |
| `--keep-cache` | не удалять промежуточные данные после успешной записи GPKG |
| `--restart` | начать загрузку заново, удалив сохранённые промежуточные данные |
| `--no-pause` | не ждать Enter перед закрытием окна |
| `--page-size`, `--timeout`, `--workers` | размер страницы WFS, тайм-аут запроса, число потоков для атрибутов |
| `--no-attributes`, `--no-protection` | не загружать подробные атрибуты выделов или защитные слои |
| `--max-quarters`, `--max-pieces` | ограничения для пробного запуска |

## Продолжение после обрыва

Всё скачанное сразу сохраняется в папке `<папка загрузки>/_cache_fgislk_<регион>_<лесничества>/`:

- `run.json` — регион, выбранные лесничества, параметры и состояние загрузки;
- каталоги `catalog`, `central`, `district`, `protection`, `quarters`, `pieces` — завершённые единицы (лесничество, квартал, защитный слой);
- `*.part.jsonl` — постраничные контрольные точки для единицы, загрузка которой была прервана;
- `attributes.jsonl` — подробные атрибуты выделов.

При потере связи скрипт не завершается, а повторяет тот же запрос с паузой от 5 до 120 секунд и продолжает работу после восстановления связи. Если окно закрыто, компьютер выключен или нажато Ctrl+C, достаточно запустить скрипт повторно с той же папкой и теми же лесничествами: уже скачанные кварталы и атрибуты берутся из сохранённого, прерванный квартал продолжается с последней полученной страницы.

После успешной записи GPKG промежуточные данные удаляются (кроме пробных запусков с `--max-quarters` или `--max-pieces` и запуска с `--keep-cache`).

## Защитные слои

Используются:

- `PROTECTIVE_FOREST` — категории защитных лесов;
- `SPECIAL_PROTECT_STEAD` — особо защитные участки лесов;
- `PROTECTIVE_FOREST_SUBCATEGORY` — ценные леса и леса, выполняющие функции защиты объектов;
- `KZL_MANAGEMENT` — категории защитных лесов по лесоустройству;
- `OZUL_MANAGEMENT` — особо защитные участки по лесоустройству;
- `PROTECTIVE_FOREST_SUBCATEGORY_MANAGEMENT` — подкатегории защитных лесов по лесоустройству.

Каждый непустой исходный слой сохраняется в GeoPackage. Пустые слои в GPKG не записываются, их число объектов указывается в таблице `metadata`; категория не подставляется предположительно.

## Поля выделов

В слое `taxation_pieces` появляются:

- `protective_category_public` — категория из `PROTECTIVE_FOREST`;
- `protective_category_management` — категория из `KZL_MANAGEMENT`;
- `protective_category` — объединённое значение из обоих источников;
- `protective_subcategory_public` — значение из `PROTECTIVE_FOREST_SUBCATEGORY`;
- `protective_subcategory_management` — значение из `PROTECTIVE_FOREST_SUBCATEGORY_MANAGEMENT`;
- `protective_subcategory` — объединённая подкатегория;
- `ozu_public` — пересекается ли выдел с `SPECIAL_PROTECT_STEAD`;
- `ozu_management` — пересекается ли выдел с `OZUL_MANAGEMENT`;
- `ozu_present` — итоговое наличие ОЗУ;
- `ozu_type_public`, `ozu_type_management`, `ozu_type` — типы ОЗУ;
- `protection_sources` — названия фактически пересекающихся слоёв;
- `protection_intersections` — число записей пересечений;
- `protection_overlap_area_ha` — сумма площадей пересечений всех тематических слоёв.

Если выдел относится к нескольким типам, значения записываются через `; `. При совпадении одной категории в публичном и лесоустроительном слое итоговое поле не дублирует текст.

## Таблица пересечений

`piece_protection_links` сохраняет отдельную запись для каждого сочетания «выдел — защитный объект — исходный слой». Поля включают:

- номер и идентификатор выдела;
- защитный слой и тип;
- идентификатор защитного объекта;
- регистрационный номер материалов лесоустройства;
- площадь пересечения в м² и га;
- долю площади выдела в процентах.

Геометрия записи — фактическая геометрия пересечения. Площади вычисляются в равноплощадной проекции `EPSG:6933`.

`protection_overlap_area_ha` в таблице выделов может превышать площадь выдела, поскольку один участок одновременно учитывается в нескольких тематических слоях. Для недублирующего анализа площадей следует пользоваться `piece_protection_links` и разделять записи по `source_layer`.

## Порог пересечения

По умолчанию игнорируются пересечения меньше 1 м², чтобы не учитывать топологические щели и касания границ:

```bash
python fgislk_export.py --region 21 --forestry 21:1 --min-overlap-m2 10
```

## Результаты

В папке загрузки создаются:

- `fgislk_<регион>_<лесничества>.gpkg` — основной результат, например `fgislk_21_1-2.gpkg` для лесничеств 21:1 и 21:2, `fgislk_21_all.gpkg` для всех лесничеств региона, `fgislk_21_7lesn_<хеш>.gpkg` при выборе более четырёх лесничеств; при пробном запуске к имени добавляется `_test`;
- `fgislk_<регион>_<лесничества>_log.txt` — журнал выполнения.

В GPKG находятся границы выбранных лесничеств и их охваты (`selected_forestry_boundaries`, `selected_forestry_bbox` — bbox каждого лесничества, `selected_area_bbox` — общий bbox; west, south, east, north в `EPSG:4326`, они же выводятся на экран), четыре административно-лесоустроительных слоя (`central_forestries`, `district_forestries`, `quarters`, `taxation_pieces`), непустые защитные слои, `piece_protection_links` и таблица `metadata` (источник, версия, выбранные лесничества, число объектов по слоям, параметры). Все геометрии записываются как MultiPolygon в `EPSG:4326`. GPKG сначала пишется во временный файл `*.partial.gpkg`; если итоговый файл открыт в ГИС, результат сохраняется под именем с датой и временем.
